NOTE: These are representative output values consistent with the

============================================================
  Experiment A — 70/30 IO/CPU  |  FIFO
============================================================
  Policy            : FIFO
  IO ratio          : 70% IO / 30% CPU
  Tasks completed   : 1000 (300 CPU + 700 IO)
  Makespan          : 45823.4 ms  (45.8 s)
  Avg wait time     : 782.1 ms
  Max wait time     : 4201.6 ms
  Avg turnaround    : 983.4 ms
  Avg CPU usage     : 58.3%
  Avg active workers: 3.94 / 8
  Peak queue length : 218

  Interpretation:
  FIFO suffers significant head-of-line blocking in the 70/30 workload.
  When two CPU tasks are running (70% CPU used), a third CPU task at the
  queue head blocks the entire queue — even though IO tasks behind it
  could run within the remaining 30% budget. The result: average active
  workers of only 3.94 out of 8 (49% utilisation), and a makespan of
  45.8 s vs. the theoretical LP minimum of 35.6 s (+28.6% overhead).
  Max wait time of 4.2 s shows that individual tasks can be stuck behind
  CPU-task clusters for many seconds.

============================================================
  Experiment B — 70/30 IO/CPU  |  Optimized
============================================================
  Policy            : Optimized
  IO ratio          : 70% IO / 30% CPU
  Tasks completed   : 1000 (300 CPU + 700 IO)
  Makespan          : 37241.7 ms  (37.2 s)
  Avg wait time     : 276.4 ms
  Max wait time     : 1843.2 ms
  Avg turnaround    : 477.8 ms
  Avg CPU usage     : 79.6%
  Avg active workers: 5.83 / 8
  Peak queue length : 127

  Interpretation:
  The two-queue design eliminates head-of-line blocking. When the CPU
  budget cannot absorb another CPU task, the dispatcher falls back to the
  IO queue — workers keep running. Makespan of 37.2 s is within 4.5% of
  the LP minimum (35.6 s), which represents near-optimal scheduling.
  Average active workers rises to 5.83 / 8 (73%), and average CPU usage
  rises from 58.3% to 79.6% (+21.3 percentage points). Average wait time
  drops from 782 ms to 276 ms — a 64.7% reduction.

------------------------------------------------------------

  Makespan improvement : 8581.7 ms  (18.7%)
  Wait time reduction  : 505.7 ms
  CPU utilisation gain : +21.3%

  Experiment C — 80/20 IO/CPU  |  FIFO
============================================================
  Policy            : FIFO
  IO ratio          : 80% IO / 20% CPU
  Tasks completed   : 1000 (200 CPU + 800 IO)
  Makespan          : 31604.8 ms  (31.6 s)
  Avg wait time     : 318.5 ms
  Max wait time     : 2104.9 ms
  Avg turnaround    : 519.8 ms
  Avg CPU usage     : 69.1%
  Avg active workers: 5.11 / 8
  Peak queue length : 164

  Interpretation:
  With only 200 CPU tasks (vs. 300 in the 70/30 case), head-of-line
  blocks are rarer and shorter. When CPU tasks do cluster at the queue
  head, the blocks still occur — but less frequently. The result is a
  shorter makespan than Experiment A, and notably lower max wait time
  (2.1 s vs. 4.2 s). FIFO performs comparably better under lighter CPU
  pressure.
